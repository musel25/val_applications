# Thesis application workflow

Read docs/OPERATIONS.md before continuing. The user authorizes local research,
tailored materials and suitable internship/thesis applications; continue past
blocked roles and ask only for genuinely missing required information.

Candidate facts and all application data are private ignored files. Start with
candidate/facts.md, candidate/cv.json, data/session.md and the SQLite tracker.
Do not copy personal details or US criteria from sibling repositories.
Use uv for every Python command. No background services, VPS or synchronization.

Use official postings, Finland first, Europe thereafter. Check deadlines and
eligibility before applying. Keep exact answer/provenance ledgers and original
artifacts; preserve blocked/interrupted attempts across sessions. Only mark
submitted after actual employer confirmation is observed and saved. Do not
invent facts, credentials, library experience, availability or authorization.
Do not complete assessments or generate an 'original' academic writing sample.

Review the existing browser tabs, avoid duplicate applications, and never use
another candidate's account. Keep a private session handoff with honest counts.
Commit each self-contained tooling/docs change using Conventional Commits, inspect
the staged file list for personal data, then immediately push each commit.
